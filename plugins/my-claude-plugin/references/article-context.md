# ArticleContext と確定タイトルの受け渡し

この文書はプラグイン内の全6スキルに適用する現行契約。会話内の同じ記事について、最新の ArticleContext を参照する。別の記事のコンテキストを混ぜない。

## 表現と互換性

- 標準は既存の `## ArticleContext` Markdown ブロック。確定タイトルは `- **タイトル（確定）**: ...` と表す。未確定ならこの行を省略する。
- JSON 入力も受け付ける。対応は theme=テーマ、targetAudience=想定読者、purpose=目的、keyMessages=伝えたい要点、primaryExperiences=一次情報・体験談、style=文体、medium=用途、outline=確認済み構成案、confirmedAt=確認日時、title=タイトル（確定）。
- `title` はユーザーが確定した非空文字列だけ。空文字・空白のみ・null・未指定は未確定。候補・仮題・空欄用の表記を確定値にしない。
- Markdown と JSON は同じ値の別表現。同じ最新コンテキスト内で両者のタイトルが異なる場合は黙って優先順位を付けず、ユーザーに採用値を確認してからタイトルに依存する処理を続ける。
- Markdown を JSON に写す場合、箇条書きは配列、構成案は改行を保持した文字列とする。未知のフィールドも元の名前・値で残す。元が JSON の場合は既存のキー・値・型（未知のフィールドを含む）をそのまま保持する。

## 更新と工程の境界

- article-title-suggestion は明示的な確定時だけタイトルを更新する。他の ArticleContext フィールドを変更せず、更新後の全文を出力する。ArticleDraft はタイトルも本文も変更しない。
- 確定時は Markdown サマリーと更新済み ArticleContext を Markdown・JSON の両方で出力する。コンテキストがない本文単独入力ではサマリーのみとし、架空の ArticleContext を作らない。
- タイトル確定は構成承認ではない。writer は `確認日時` / `confirmedAt` と承認済み構成を従来どおり確認する。タイトル確定によって確認日時を補完しない。
- writer は確定タイトルを H1 にそのまま使用し、別案の行・新しいタイトル案3本を省略する。未確定なら従来の3案を生成する。
- ドラフト生成後にタイトルを確定した場合、旧ドラフトはそのまま残る。writer に「確定タイトルを反映して」と依頼されたら H1 と旧別案行だけを更新し、本文を保持する。
- reviewer は最新の確定タイトルで整合性を評価する。勝手に改題しないが、本文との不一致・誤解を招く表現は指摘する。旧ドラフトの見出しとの相違も指摘する。
- editor は確定タイトルを参照しつつ、従来どおり原文を保持して編集指示だけを追加する。旧ドラフトの見出しが異なる場合は writer に反映を依頼する旨を添える。
- thumbnail はドラフトの有無にかかわらず確定タイトルを掲載テキストの第一候補にする。短縮案は画像用の別案と明示し、確定タイトル自体を書き換えない。未確定でドラフトがある場合のみ従来の3案を参照する。
- facilitator が同じ記事のコンテキストを再出力する場合は確定タイトルを保持する。テーマ変更でタイトルと矛盾する場合は再確認し、黙って削除・改題しない。

## プラグインのスキル名

ディレクトリ名と frontmatter の name を一致させる。正式名は `article-title-suggestion`。統合元の `title-suggestion-agent` は旧ディレクトリ名であり、実行用の別名は作らない。
Claude Code プラグインの呼び出し例は `/my-claude-plugin:article-title-suggestion`。他の5スキルも同じ名前空間を使う。
