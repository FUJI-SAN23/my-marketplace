## V1: フェーズゲート G1 — ArticleContext なしで article-writer を起動

### テストシナリオ

会話履歴に `## ArticleContext` セクションが存在しない状態で、ユーザーが「ドラフトを作成してください」と入力する。

### 期待する動作

```
article-writer が以下のメッセージを返し、処理を停止する:

「ドラフトを生成するには、まず article-facilitator で記事の企画・構成を確定してください。

『記事の構成を考えたい』と入力すると article-facilitator が起動します。」
```

### 検証ポイント

- [x] article-writer が ArticleContext の欠如を検出する
- [x] エラーメッセージを出力して処理を停止する（ドラフトを生成しない）
- [x] article-facilitator への案内メッセージが含まれている

### SKILL.md 該当箇所

`article-writer/SKILL.md` の「フェーズゲート G1 チェック（最初に必ず実行）」セクション参照。

### 期待する動作

article-facilitator で構成案を確認・承認してから再度お試しください。」

### 検証ポイント

- [x] `確認日時` の欠如を検出する
- [x] ドラフト生成を行わずに停止する
- [x] article-facilitator へ戻るよう案内する

### SKILL.md 該当箇所

`article-writer/SKILL.md` の「フェーズゲート G1 チェック」内の「ArticleContext が存在するが確認日時が設定されていない場合」参照。

## V3: 部分修正フロー — 特定 H2 見出しの修正

### テストシナリオ

シナリオA のドラフト生成後、ユーザーが「『なぜコンテンツ販売は最初に稼げないのか』の H2 セクションを、より具体的な数字を使って書き直してください」と入力する。

### 期待する動作

```
article-writer が以下を実行する:

1. 「以下の箇所を修正しました: なぜコンテンツ販売は最初に稼げないのか（H2）」と宣言する
2. 該当 H2 セクション（小見出し含む）のみを修正して提示する
3. 他のセクション（導入・売れるコンテンツの考え方・5ステップ・まとめ等）は変更しない
```

### 検証ポイント

- [x] 指定された H2 セクションのみが修正される
- [x] 他のセクションが変更されていないことを明示する
- [x] 修正後に「以下の箇所を修正しました」サマリーが出力される
- [x] 記事全体の再生成を行わない

### SKILL.md 該当箇所

`article-writer/SKILL.md` の「フェーズ 3: 部分修正モード」参照。

## V4: 文体統一フロー — 断定調指定

### テストシナリオ

シナリオC の ArticleContext（文体: 断定調）を使用して article-writer でドラフトを生成する。

### 検証ポイント

- [x] 導入文が断定調（「〜はずだ」「〜だろう」「〜する」）で記述されている
- [x] 本文の各セクションが断定調で統一されている
- [x] まとめが断定調で締まっている
- [x] 敬語・丁寧語（「〜です」「〜ます」「〜ください」）が使用されていない
- [x] 不足情報リスト・推測箇所リストも断定調で記述されている

### 期待する確認箇所

シナリオC ドラフト（scenario-c-draft.md）の文末表現を確認:
- ✅ 「踏み出せない」「重くのしかかってきた」「止まらなくなった」（断定調）
- ✅ 「リスクである」「可能だ」「集中していた」（断定調）
- ✅ 「記述する」「位置づけましょう」→ シナリオC では「位置づける」に統一されるべき点を確認要

### SKILL.md 該当箇所

`article-writer/SKILL.md` の「文体の統一」セクション参照。

## V5: Markdown 出力の構造的妥当性

### 検証対象

すべてのシナリオ（A・B・C）の draft ファイル。

### 検証ポイント

- [x] ファイルが有効な Markdown 形式である
- [x] タイトル（# 見出し）が1つ存在する
- [x] 別案タイトルが括弧内に記載されている
- [x] H2 見出し（## ）が本文構成として使用されている
- [x] H3 見出し（### ）が H2 の下位として使用されている
- [x] コードブロック（\`\`\`）が適切に開閉されている（シナリオB のみ該当）
- [x] 表（| 列 |）が有効な Markdown 表形式である
- [x] 不足情報リスト・推測箇所リストが必須セクションとして存在する

### 構造確認コマンド（参考）

```bash
# タイトル確認
grep -c "^# " examples/output/scenario-a-draft.md  # 期待: 1

# H2 見出し数確認
grep -c "^## " examples/output/scenario-a-draft.md  # 期待: 3以上

# 必須セクション確認
grep "^## 不足情報リスト" examples/output/scenario-a-draft.md
grep "^## 推測箇所リスト" examples/output/scenario-a-draft.md
```

## V6: 一次情報と一般論の区別

### 検証対象

シナリオC ドラフト（scenario-c-draft.md）—一次情報が最も豊富なシナリオ。

### 検証ポイント

- [x] ユーザーが提供した体験談に `【一次情報】` タグが付いている
- [x] 一般的なノウハウ・アドバイスには `【一次情報】` タグが付いていない
- [x] `【一次情報】` と一般論が同一段落内で混在していない
- [x] ArticleContext に記載された体験談の数値（年収・期間・件数）が正確に使用されている

### 確認方法

```bash
# 一次情報タグの使用箇所を確認
grep -n "【一次情報】" examples/output/scenario-c-draft.md
```

- 4ヶ月を振り返ると3フェーズ
- 職務経歴書を7回書き直した
- エージェント2社並行利用
- 面接質問80%が3つに集中
- 年収交渉しなかった後悔

- 実際の Claude Code セッションでの動的検証（ユーザーとのインタラクティブな会話フロー）は別途実施が必要
